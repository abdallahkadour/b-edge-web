Buttons — bedge-button

The single button primitive. 4 variants × 3 sizes. Source: projects/shared/src/lib/ui/button.component.ts.

Variants (size md)
Sizes (primary)

<bedge-button variant="primary" size="md" [fullWidth]="true" [loading]="loading()" (click)="submit()"> Sign in </bedge-button> variant: 'primary' | 'secondary' | 'ghost' | 'danger' (default 'primary') size: 'sm' | 'md' | 'lg' (default 'md') USAGE RULE — button hierarchy on a screen: Exactly one primary button per view/section. Row-level or secondary actions use 'secondary' or 'ghost', never 'primary' — this was a real bug fixed in orders.component.html and bookings.component.html, where per-row buttons were competing visually with the page's actual primary action.

Cards — bedge-card

Surface container. Existed with 4 different border shades and 3 different radii before this — including one non-existent class, border-gray-150, that silently rendered with no border at all.

padded (default)
p-4, standard content card
flush
No built-in padding — for cards owning their own internal layout (e.g. list rows, image + content)
interactive
Adds hover border + pointer — hover to see it
<bedge-card padding="padded" [interactive]="false">...</bedge-card> Base (always): bg-white border border-gray-200 rounded-xl padding: 'padded' → +p-4 | 'flush' → no padding interactive: true → +hover:border-gray-300 transition-colors cursor-pointer

Inputs — bedgeInput

An attribute directive, not a wrapper component — deliberate, so it works with both reactive forms and template-driven ngModel without a ControlValueAccessor. The directive does not set height — callers add h-11 (standard field) alongside it.

Enter a valid email address.

<input bedgeInput [invalid]="touched() && !isEmailValid()" class="h-11" ... /> <textarea bedgeInput class="text-sm resize-none" rows="4" ...></textarea> Directive classes (always): w-full px-3.5 rounded-lg border text-[15px] outline-none transition-colors placeholder:text-gray-400 disabled:bg-gray-50 disabled:text-gray-400 [invalid]=true → border-danger [invalid]=false → border-gray-200 focus:border-ink PATTERN — error text below a field: a fixed-height slot (mt-1.5 h-4), always present whether or not an error shows, so the layout below the field never jumps. See login.component.html.

Page container width

Dashboard list/detail screens: max-w-4xl mx-auto. Auth/form screens (narrower, single card): max-w-sm. Mobile-only PWA screens: full width, no max — the viewport itself is the constraint.
